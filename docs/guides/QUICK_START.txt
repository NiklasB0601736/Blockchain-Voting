QUICK START - BLOCKCHAIN VOTING PROTOTYP
========================================

1. INSTALLIEREN
---------------

    python3 -m venv .venv
    source .venv/bin/activate
    .venv/bin/pip install -r requirements.txt

Node.js ist fuer den normalen Start nicht erforderlich. Das Browser-Crypto-
Bundle ist bereits gebaut.


2. HTTPS EINMALIG VERTRAUEN
---------------------------

TLS-Material erzeugen:

    npm run tls:generate

Alternativ wird es beim ersten Start automatisch unter `.node-data/tls/`
erzeugt. Damit der Browser keine Warnung zeigt, die Datei

    .node-data/tls/development-ca.pem

einmal in den Zertifikatsspeicher importieren und als vertrauenswuerdig
markieren. Auf macOS: Schluesselbundverwaltung -> System -> Importieren ->
Zertifikat oeffnen -> Vertrauen -> Immer vertrauen. Danach den Browser neu
starten.

Die Datei `development-ca-key.pem` ist privat und darf nicht weitergegeben
werden.


3. DEMO STARTEN
---------------

    .venv/bin/python scripts/v2_node_launcher.py

Im Node Controller:

    1. Optional "Demo-State vorher resetten" aktivieren.
    2. "3-Node-Demo starten" auswaehlen.
    3. Auf die Startmeldungen aller vier Prozesse warten.
    4. "Demo Links oeffnen" auswaehlen.

Direktstart ohne GUI:

    .venv/bin/python scripts/run_v2_demo_network.py --reset

Adressen:

    Node 1     https://127.0.0.1:5001/dashboard
    Node 2     https://127.0.0.1:5002/dashboard
    Node 3     https://127.0.0.1:5003/dashboard
    Committee  https://127.0.0.1:5001/committee
    Voter      https://127.0.0.1:7000/?node=https://127.0.0.1:5001
    API Docs   https://127.0.0.1:5001/docs

Lokale Rollenkeys:

    Admin Key  dev_admin_key
    Node Key   dev_node_key


4. WAHL DURCHFUEHREN
--------------------

Dashboard, Node 1:

    1. Titel, Kandidaten, Zeitraum, Member Count und Threshold setzen.
    2. "Wahl und Committee erzeugen" auswaehlen.
    3. Alle privaten Committee-Share-Dateien getrennt speichern.
    4. Mempool als Block minen.

Separater Voter Client:

    5. Wahl laden und ein Demo-Secret eingeben.
    6. Registrieren.

Dashboard, Node 1:

    7. Registrierung als Block minen.

Voter Client:

    8. Kandidaten auswaehlen und verschluesselt waehlen.
    9. Transaktionsstatus anzeigen.

Dashboard, Node 1:

   10. Vote-Block minen.
   11. Wahl mit dem Admin Key beenden und diese Transaktion minen.

Dashboard, Node 2 und Node 3:

   12. Mit dem Node Key synchronisieren.
   13. Gleiche Chain-Laenge und gleichen letzten Blockhash pruefen.

Committee Client:

   14. Wahl laden.
   15. Mindestens den Threshold unterschiedlicher Share-Dateien laden.
   16. Tally publizieren.

Dashboard, Node 1:

   17. Tally-Transaktion minen.
   18. "Verify" ausfuehren.

Erwartung:

    result_status = verified
    complete      = true

Registrierung und Vote koennen technisch auch in dieser Reihenfolge im selben
Mempool und Block liegen. Getrennte Blocks machen den Ablauf in der
Praesentation leichter nachvollziehbar.


5. TESTEN
---------

    .venv/bin/python -m unittest discover -s tests
    npm run test:web-crypto


6. WICHTIGE GRENZE
------------------

Die Demo prueft keine reale Identitaet oder Wahlberechtigung. Eligibility- und
Ballot-ZK-Proofs sind Platzhalter. Die lokale CA, der einzelne Validator, die
JSON-Persistenz und die vom Admin-Browser erzeugten Committee-Shares sind nicht
fuer reale Wahlen ausgelegt.

Die vollstaendige Dokumentation und Fehlerbehebung stehen in `README.md`.
